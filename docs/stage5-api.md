# Stage 5 — Frozen A3 FastAPI inference service

Stage 5 serves the immutable `returnguard-a3-v1` model-of-record through a
small FastAPI process. It is a lifecycle boundary, not a new modelling stage:
it does not train, tune, calibrate, promote a registry version, access ASOS raw
data, or evaluate the official test split.

## Run locally

Install the pinned serving environment:

```bash
.venv/bin/pip install -r requirements.txt -c constraints-stage5.txt
```

The ignored local MLflow registry must already contain `returnguard-a3` with
its explicitly governed `model-of-record` alias. The normal Stage 4 rebuild
creates the registered artifact; promotion remains an explicit governance
action. Start the server with:

```bash
.venv/bin/uvicorn backend.main:app --reload
```

The OpenAPI document and Swagger UI are generated by FastAPI at
`/openapi.json` and `/docs`.

## Frozen model loading and provenance

At FastAPI lifespan startup, `ModelService` loads exactly once from
`models:/returnguard-a3@model-of-record` using `mlflow.pyfunc.load_model`. It
also resolves the alias using `MlflowClient` and fails closed unless all of the
following agree:

- registry model `returnguard-a3`, registered version, semantic version
  `returnguard-a3-v1`, and `model_of_record` governance tag;
- MLflow metadata for the semantic version, feature-manifest hash, and
  freeze-spec hash;
- the committed frozen lifecycle manifest;
- the composite artifact's 41 ordered transformed features and exactly its
  donor-imputation, derived-price, and preprocessing steps.

The service makes one non-sensitive synthetic startup prediction. It retains
only validated safe provenance in process memory. It does not reload MLflow,
read a dataset, or touch disk for ordinary requests.

`GET /health` is a pure process liveness response. A model-loading failure
leaves it available (`200`) while `GET /ready` and model endpoints return
safe `503 model_unavailable` responses. Public responses never contain local
paths, SQLite URIs, stack traces, full MLflow metadata, or raw exception text.

## Request contract

One request represents one **customer × product-variant purchase event**. The
caller sends raw pre-preprocessing values only:

```json
{
  "customer_context_key": "opaque-stable-token",
  "customer_profile": {
    "yearOfBirth": 1988,
    "isMale": false,
    "shippingCountry": "Country_A",
    "premier": true
  },
  "product_profile": {
    "productType": "Jeans",
    "brandDesc": "Brand_A",
    "avgGbpPrice": 54.99,
    "avgDiscountValue": 15.0
  }
}
```

The API rejects unknown body fields. Callers cannot supply encoded features,
derived features, product-frequency features, labels, aggregates, raw ASOS
identifiers, or redundant source dummies. The governed artifact performs all
fitted preprocessing; the API does not recreate it.

For a known `customer_profile`, `isMale`, `shippingCountry`, and `premier` are
required; `yearOfBirth` is optional. `1900` is a historical ASOS missing-value
sentinel, so callers must send `null` rather than `1900`. Clearly implausible
birth years are rejected. Valid years outside observed training support
(1890–2020) remain scoreable and produce a warning.

`customer_profile` may instead be `null`, but then `customer_context_key` is
required. The opaque key is mapped only to the artifact's customer routing
column, which the fitted donor imputer uses for a stable donor selection. It
is not a transformed model feature, is never logged, returned, or explained,
and changing it for a complete profile cannot change the score. The same
missing-profile key remains stable across repeated calls, batches, and row
orders. Different missing-profile keys can legitimately choose different
stable synthetic donors. Donor demographics are never revealed as customer
facts.

`product_profile` may be complete, partial, or `null`. Categorical nulls are
mapped internally to the frozen missing-category behavior; numeric nulls pass
through as missing to the frozen derived-feature and XGBoost paths. Literal
`"__MISSING__"` is rejected; use JSON `null`. Price must be finite and greater
than zero; discount must be finite from 0 to 100. Valid price values outside
the observed £1.25–£518 support and discounts above observed 45.3 receive a
warning. Unknown categories are accepted and ignored by the frozen one-hot
encoder, with only field names surfaced in `unknown_categories`.

Incomplete products remain scoreable, but every such response warns that
product-missing events had materially weaker evaluation performance.

## Endpoints and public responses

| Endpoint | Purpose |
|---|---|
| `GET /health` | Process liveness; never contacts MLflow. |
| `GET /ready` | Readiness after model and provenance validation. |
| `GET /model` | Safe model/version/dataset/governance provenance and limitations. |
| `POST /predict` | One event score. |
| `POST /predict/batch` | 1–100 events in one vectorized DataFrame and one model call. |
| `POST /explain` | One event score plus grouped, non-causal Tree SHAP factors. |

`POST /predict` returns a deterministic, monotonic 0–100 score rather than a
raw model probability. There are no Low/Medium/High risk bands because no
business-loss thresholds have been established.

```json
{
  "request_id": "server-generated-uuid",
  "risk_score": 67,
  "risk_score_scale": "0-100",
  "score_type": "dataset_conditional_return_risk",
  "data_context": {
    "customer_profile_imputed": false,
    "customer_birth_year_imputed": false,
    "product_profile_available": true,
    "product_profile_complete": true,
    "missing_product_fields": [],
    "unknown_categories": [],
    "outside_training_range_fields": []
  },
  "warnings": [],
  "model": {
    "semantic_version": "returnguard-a3-v1",
    "registry_model": "returnguard-a3",
    "registry_version": "1",
    "feature_manifest_hash": "75834b5b..."
  },
  "methodology_note": "This score is estimated from a returner-enriched ASOS research sample. It supports relative risk ranking but is not a merchant-wide probability of return. Model factors describe model behavior and are not causal."
}
```

The public API never returns a raw model probability or margin, raw SHAP
value/magnitude, encoded feature name, technical donor routing value, donor
demographic, or a causal claim. `/explain` performs Tree SHAP internally in
raw-margin space but returns only grouped display factors and directions such
as `{"display_name": "Product type: Jeans", "direction": "lower"}`. It
suppresses all customer-demographic groups when the profile was donor-imputed.

Set `RETURNGUARD_EXPLANATIONS_ENABLED=false` to disable this optional endpoint;
it then returns stable `503 explanations_disabled` while prediction remains
available.

## Configuration, errors, and privacy

Configuration is resolved once when the process starts:

| Variable | Default |
|---|---|
| `RETURNGUARD_MLFLOW_TRACKING_URI` | Repository-local MLflow SQLite URI |
| `RETURNGUARD_MODEL_URI` | `models:/returnguard-a3@model-of-record` |
| `RETURNGUARD_LOG_LEVEL` | `INFO` |
| `RETURNGUARD_MAX_BATCH_SIZE` | `100` (permitted range 1–100) |
| `RETURNGUARD_EXPLANATIONS_ENABLED` | `true` |
| `RETURNGUARD_CORS_ORIGINS` | `http://localhost:3000` |

Browser access is intentionally an explicit origin allowlist. The default is
the local Stage 6 development server; methods are limited to `GET` and `POST`,
and credentials are not allowed. A deployment must set only its trusted UI
origins rather than using a wildcard.

For frozen-model governance, a `RETURNGUARD_MODEL_URI` override is accepted
only when it identifies the same `model-of-record` alias or that alias's exact
currently resolved registry version. It cannot select a challenger or stale
model version.

`422 invalid_request` covers body, numeric, sentinel, reserved-token, missing
key, and batch validation. `503` covers unavailable model or disabled
explanations. `500 inference_failed` and `500 explanation_failed` are
sanitized unexpected serving errors. Error bodies include a server-generated
request ID and stable code, never technical details.

Structured logs retain only request ID, endpoint, status, latency, batch size,
safe model version, boolean missingness context, and aggregate warning counts.
They never persist request bodies, opaque context keys, demographics, product
attributes, scores, raw identifiers, or explanation factors. Stage 5 is
stateless: it has no prediction database or caching layer.

## Initial local performance check

With the pre-existing local model-of-record warm in an in-process FastAPI
client on the validated development machine, the initial engineering check
measured the following median / p95 latencies over 20 warm calls: one prediction
**4.15 / 4.66 ms**, a 100-event vectorized batch **6.04 / 6.70 ms**, and one
explanation **6.78 / 7.01 ms**. These are local engineering measurements rather than
network-inclusive SLAs; no cache, queue, or external infrastructure was added.

## Verification

The ordinary suite has no ASOS raw-data or local-MLflow dependency:

```bash
.venv/bin/ruff check .
.venv/bin/pytest -m "not raw_training_data and not historical_test_data and not full_rebuild and not local_registry"
```

The optional integration test starts the app with the pre-existing local
model-of-record and checks readiness, provenance, deterministic repeat and
missing-customer scoring, and vectorized batch order. It does not train or
load an official test evaluator:

```bash
.venv/bin/pytest tests/api/test_local_registry_integration.py -m local_registry -q
```

The official ASOS test result remains historical frozen evidence. Stage 5
normal serving paths and CI do not open test labels or invoke final evaluation.
